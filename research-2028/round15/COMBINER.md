# A compact composite KEM with one established component

The sender runs two independent encapsulations, combines their shared secrets with both ciphertexts, and sends the two ciphertexts. The recipient uses both private keys to reproduce the result. The SG-DIFRA component computes the actual Round 14 ternary finite difference, sparse private checks and error correction. In the compact profile the security argument can rely entirely on the other component. This permits an end-to-end security claim without assigning a numerical hardness estimate to the small SG-DIFRA parameters.

The [Classic McEliece comparison](CLASSIC.md) records a 2026 advisory against new designs using that component. The theorem states what follows if either component is secure. The compact native component has no independent strength rating. The standalone research claim is in the [native proof](NATIVE_PROOF.md).

## Wire profiles and algorithms

The [implementation](hybrid_kem.py) accepts a fixed-width independent component producing a 32-byte shared secret. For the ML-KEM profiles its first component is the [FIPS 203 provider adapter](reviewed_kem.py). Its second component uses the Round 14 two-seed KEM with 256 message bits, $h=8,n=3,m=640,w=3,z=2$, 128 bits of sender-sampling slack, a 32-byte nonce and the RS outer code with 180 trits. The two per-key expansion slacks are 320 bits each. These small dimensions prioritize bandwidth and exact native decoding. No security strength is assigned to the native component here.

| Compact ML-KEM-backed composite | Public key bytes | Standalone private key bytes | Ciphertext bytes | Shared key bytes |
|---|---:|---:|---:|---:|
| ML-KEM-512 plus SG-DIFRA | 1,332 | 128 | 963 | 32 |
| ML-KEM-768 plus SG-DIFRA | 1,716 | 128 | 1,283 | 32 |
| ML-KEM-1024 plus SG-DIFRA | 2,100 | 128 | 1,763 | 32 |

The native contribution to each row is 532 public bytes, 64 private bytes and 195 ciphertext bytes. ML-KEM contributes its raw encapsulation key and ciphertext plus a regenerable 64-byte private seed. Suite selection is authenticated out of band. The fixed widths of the selected suite determine parsing. The component order is always the established algorithm first, SG-DIFRA second.

* **Key generation.** Generate both component keypairs with independent randomness. Concatenate the public keys and the private keys separately. In the optional cached-public variant include a 32-byte public-context digest at the end of the private key.
* **Encapsulation.** Generate $(c_1,K_1)$ and $(c_2,K_2)$ independently. Transmit $c_1\Vert c_2$. Derive a 32-byte shared key by hashing the output tag, $K_1,K_2,c_1,c_2$, the public context fields, and the suite identifier in that order. The full-public variants use both literal public keys as the context. The cached-public variant uses the digest of its separate public tag, both complete public keys and its suite identifier. All hash fields, including tags, have eight-byte big-endian length prefixes. The digest and output hash both take the first 32 bytes of SHA3-384.
* **Decapsulation.** Parse the ciphertext at the fixed component boundary and run both component decapsulations. Propagate an explicit component failure. For an implicitly rejecting component, use its returned key according to its specified interface. Reproduce the same public context and apply the same output hash. The full-public variants regenerate both public keys. The cached-public format reads the digest from its private key. Its public-key and ciphertext widths remain the sums of the two component widths, and its private key is 32 bytes longer than that sum for the component private keys.

This follows the ciphertext-binding parallel construction of Giacon, Heuer and Poettering. NIST SP 800-227 §4.6.3 describes the form using both public keys. The extra length fields specify unique input strings. Truncating an ideal 384-bit random-function output to 256 bits gives a uniform 256-bit output. The cached and full formats carry distinct suite identifiers. For one honestly generated recipient the public context is fixed. The correctness and secrecy arguments require the transmitted ciphertext pair to be injectively identified in the hash input. No collision-resistance assumption on the cached **public** context is needed for that fixed-recipient conclusion. [GHP, *KEM Combiners*, Theorem 1](https://eprint.iacr.org/2018/024.pdf) · [NIST SP 800-227, §§4.6.2–4.6.3](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-227.pdf)

## Conditional IND-CCA and IND-CPA theorem

Use one honestly generated recipient, independent component algorithms and randomness, quantum-accessible ideal hashing, and adaptive **classical** requests to the composite decapsulation oracle. The adversary may not request the complete challenge ciphertext after receiving it. The two component keys have a prescribed 256-bit output space. Only the combined decapsulation interface is exposed. Fix either component $i$ and suppose its raw KEM IND-CCA distinguishing gap is bounded by $a_i$ for the reductions' actual resources in this environment. Let $f_i$ be its average honest key-disagreement probability. Let $b_i$ bound the raw split-key pseudorandomness gap of the output hash when component key $i$ is independently uniform and hidden. Then a bound on the raw composite distinguishing gap is

$$\Delta_{\mathrm{CCA}}\le\min(1,\;2a_i+2b_i+2f_i).$$

The theorem applies separately to either component. In particular the ML-KEM-based guarantee requires the specified ML-KEM assumption and ideal hash modeling, and makes **no hardness assumption about small SG-DIFRA**. The same statement with zero decapsulation queries covers IND-CPA. Honest composite disagreement is at most the sum of the two component disagreement probabilities. The SG-DIFRA component has perfect honest agreement, so in the ML-KEM rows this probability is at most ML-KEM's honest disagreement probability. FIPS 203 specifies its small nonzero rates in Table 1. [FIPS 203, §§3.2–3.3 and Table 1](https://nvlpubs.nist.gov/nistpubs/FIPS/NIST.FIPS.203.pdf)

**Proof.** Let the challenge component ciphertext be $c_i^*$. The simulator generates all other private keys. It sends every required decapsulation query on a different $i$th ciphertext to the secure component's oracle. When a composite query reuses $c_i^*$ alongside a different second ciphertext, it uses the supplied challenge component key for that slot and runs the other private decoder normally. Repeated composite queries receive consistent replies. On the honest challenge-agreement event this game exactly reproduces the original real-key game. The probability of changing an observable outcome by this substitution is at most $f_i$.

Before challenge delivery the simulation uses honest decapsulation and caches every reply, including failures. Later repeats receive the cached reply. The keyed split-PRF oracle is used at challenge delivery and on fresh postchallenge pairs under the hidden slot. The published two-stage game permits a phase-one query that happens to equal the future challenge; its phase-one answer used the ordinary hash.

The component IND-CCA game permits replacing that challenge component key by a fresh uniform hidden string for a cost at most $a_i$. The split-key PRF game then replaces the output on each fresh ciphertext pair using this hidden slot by a uniform output for a cost at most $b_i$. A valid query with a different companion ciphertext has a different transcript from the challenge even when both component secrets coincide. The case where the other component rejects needs no hash response. The full challenge key in the middle game is uniform and independent of those decapsulation outputs. Undoing the split-key and component replacements on the random-key side costs at most $b_i+a_i$, and undoing the challenge-component decapsulation substitution costs at most another $f_i$. This is the two-stage hybrid argument of GHP Theorem 1, with its table of previously answered decapsulations and the two correctness terms shown explicitly. The reductions are straight-line classical-interface simulations. Quantum internal computation is allowed when the underlying assumptions grant that adversary class.

**Why the hash premise has a quantum justification.** Don, Fehr and Huang prove the hash-based split-key PRF in the quantum random-oracle model. Their Theorem 2 applies directly to the injectively framed input in this implementation. Given the other fields and any fixed hash address, at most one value for the hidden 256-bit key could produce the address. Their maximum point-probability parameter is consequently $2^{-256}$. Distinct composite ciphertexts also satisfy their fresh-input condition. In their notation a bound on $b_i$ is
$$4\sqrt{2q_O^2q_H2^{-256}}+4\sqrt{2q_H^2q_O2^{-256}},$$
clipped at one, with at most $q_D+1$ classical split-key evaluations for $q_D$ composite decapsulation queries. The direct quantum hash-query count $q_H$ must include the entire tester's resources. Independent component oracle domains remain available to the reductions. Concrete SHA3-384 and the other hashes instantiate these idealizations. For example, inserting even $q_O=1$ and $q_H=2^{191}$ makes the second term exceed one. At that budget this bound is vacuous. This is a limitation of the estimate. The formula supplies no $2^{191}$ quantum work estimate, and a fixed 256-bit key width gives no asymptotic claim by itself. [Don, Fehr and Huang, *Adaptive versus Static Multi-oracle Algorithms, and Quantum Security of a Split-key PRF*, §4, Theorem 2](https://arxiv.org/pdf/2206.08132)

## Executable scope

The [tests](test_hybrid_kem.py) run both parties at the three composite ML-KEM sizes and independently rebuild the shared key from the two component decapsulations and serialized fields. They cover the full-public and cached-public formats, a fixed hash vector, rejection, canonical widths and a mixed pair of valid component ciphertexts. This is a research implementation of a composite protocol. FIPS 203 standardizes the ML-KEM ingredient. The proof concerns ideal protocol interfaces, with no side-channel, malicious-component, validation or concrete SG-DIFRA strength certification.
