# From differential encryption to chosen-ciphertext key encapsulation

The native public-key encryption (PKE) encrypts one encoded message into a ternary body. The private decoder recovers the message using its sparse checks and the public error-correcting encoding. This note specifies the KEM built on that message decoder. The proof uses the explicit-reject Fujisaki–Okamoto transform. It requires quantum IND-CPA security for the actual PKE distribution and perfect honest message recovery. It places no requirement on recovering the sender's masking vector, noise positions or other encryption coins. [Hövelmanns and Majenz, Theorem 1, Definitions 1 and 6, Figure 7](https://eprint.iacr.org/2023/1811.pdf)

## Randomized base encryption and spread

Let $k$ be the public key. The message space is the full set of $\ell$-bit strings. A deterministic injective conversion maps each such string to the message symbols for the public error-correcting code. The decoder rejects values outside the message alphabet or bit-string image. Let $E(k,m;r)$ denote the canonically serialized native body given a fixed randomness tape. For the base encryption used in the theorem, include an independent uniform $s$-bit nonce $u$ in the ciphertext. The resulting ciphertext contains the two unambiguously encoded fields $u$ and $E(k,m;r)$ in the protocol's fixed order. Base decryption can ignore $u$ after checking syntax.

For fixed $k,m$ and a particular complete ciphertext, its nonce already has a specified value. The ciphertext probability under randomized encryption is therefore at most $2^{-s}$. This establishes the theorem's spread parameter $\gamma\ge s$. The nonce preserves the base PKE's IND-CPA bound because a challenge simulator can attach an independent uniform nonce to the supplied native body. The nonce is transmitted and counted in ciphertext bytes.

The random tape for $r$ has fixed finite length. For a uniform choice from $A$ possibilities, a block of $b\ge\lceil\log_2 A\rceil+\sigma$ random bits, interpreted as an integer modulo $A$, produces a rank within total variation distance $2^{-\sigma}$ of uniform. Indeed each rank has either $\lfloor 2^b/A\rfloor$ or $\lceil 2^b/A\rceil$ preimages. The implementation uses one joint rank. Its range has size $A=3^{h+n}\binom{N}{z}2^z$, where $h+n$ counts the uniform input trits, $N$ is the body length in trits, and $z$ is the error weight. Public unranking of a uniform rank would give the ideal ternary input vector and independently signed error support. With the implemented bit tape the entire coin distribution satisfies $\nu\le 2^{-\sigma}$. Exact rejection sampling in key generation samples the specified key distribution. The nonce receives its own equally distributed bits. All tapes, including those mapping to more frequent ranks, produce legal randomness with the specified weight. Thus perfect message recovery for every such encryption survives finite-tape sampling.

More generally, let $\nu$ bound the distance between the actual body coins and the ideal law used in the base proof. For independent blocks a sum of their individual bounds suffices. Changing the coins for the one challenge ciphertext changes the observed event probability by at most $\nu$ for each of the two challenge messages. Consequently a raw base PKE IND-CPA gap $\epsilon_{\rm ideal}$ implies a bound $\epsilon=\epsilon_{\rm ideal}+2\nu$ for finite-tape randomized encryption, clipped at one. In the notation of the [base proof](BASE_PROOF.md), one may take $\epsilon=\min(1,2t\epsilon_1+2\epsilon_2+2\nu)$ for exact key generation. This comparison is before the FO transform. There is no replacement of an entire quantum oracle by a statistically close one in this argument. Any difference in the *key generation* law must be accounted for separately. A base proof already formulated for the implementation's exact key and coin laws uses its own $\epsilon$ directly.

## Algorithms

Use independent ideal hash functions $G$ and $H$, with quantum query access. For a fixed suite and recipient key, $G$ maps an $\ell$-bit message to one full tape for the nonce and the body, with the lengths and order specified by that suite. $H$ maps a message to the shared-key space, here 32 bytes. The implementation must bind any suite and public-key context identically on both sides and use disjoint domains for the two functions. Injective framing of a fixed target context gives exactly the two independent random functions on that context in the ideal model. Other strings form independent hash slices. Where those slices are exposed, the base quantum assumption and resource budget include access to this independent auxiliary oracle. The hash abstraction is separate from the concrete SHAKE implementation.

* **KeyGen.** Generate the native PKE keys. The recipient has the canonical public key or can reproduce it when the framing includes that key.
* **Encaps.** Draw $m$ uniformly from all $\ell$-bit messages. Use $G(m)$ as the entire randomness tape to encrypt $m$, producing the complete ciphertext $c$. Return $c$ and $H(m)$.
* **Decaps.** Parse the ciphertext canonically and recover a candidate $m'$ using the native secret key. Reject a parsing or decoding failure. Encrypt $m'$ again using the entire $G(m')$ tape. Compare every ciphertext byte, including the nonce. Return $H(m')$ exactly on equality and an explicit failure symbol otherwise.

Every valid sender tape produces a body from which the private decoder recovers its original message. The two evaluations of $G$ therefore agree and the ciphertext check passes for every honest encapsulation. Both parties derive the same key.

## Security theorem and its premise

Use a single honestly generated recipient key, two independent quantum random oracles and adaptive **classical** decapsulation queries excluding the canonical challenge ciphertext. Let $q_G,q_H,q_D$ bound the numbers of queries to $G,H$ and decapsulation, and let $d$ be the combined quantum query depth for $G,H$. Set $q=q_G+q_H$. Let $\epsilon$ upper-bound the raw IND-CPA gap for the base PKE against the quantum adversary obtained by the reduction, including its simulation time and quantum memory. Theorem 1 of Kathrin Hövelmanns and Christian Majenz then gives the following bound in the repository's **raw KEM gap** convention:

$$
\Delta_{\rm KEM}\le\min\!\left(1,\;
8\sqrt{(d+q_D)\epsilon}
+16(q+q_D)2^{-\ell/2}
+48q_D(q_G+4q_D)2^{-s/2}
\right).
$$

Their base PKE advantage is the raw difference between two acceptance probabilities. Their KEM advantage is the amount by which guessing success differs from one half. Converting the latter to a raw gap doubles the bound. The worst-case decryption error term vanishes by perfect correctness. The theorem's simulator has additional extractable-oracle simulation time and memory, so the resource budget used for $\epsilon$ must cover those costs. [Author version, Theorem 1, p. 9 and Definitions 2 and 6](https://eprint.iacr.org/2023/1811.pdf) · [PQCrypto 2024 publication, pp. 245–265](https://doi.org/10.1007/978-3-031-62746-0_11)

The published game gives the challenge at the start. If the adopted convention permits up to $q_{\rm pre}$ classical decapsulations before challenge delivery, add at most $2q_{\rm pre}/2^\ell$ to the raw bound and clip at one. To see this, presample the independent uniform message and hide the challenge during phase one. For fixed keys and hashes, exact decryption makes the deterministic FO ciphertext function injective in that message. Thus a prechallenge transcript in the original unrestricted game names the future ciphertext with probability at most $q_{\rm pre}/2^\ell$. Coupling the original game to one blacklisting that ciphertext throughout changes each world's output probability by at most this amount. The modified game is simulated by withholding the challenge from the adversary until phase two.

For an asymptotic family, take the sampling slack large enough that its bias is negligible. For polynomial query budgets, negligible base quantum IND-CPA advantage and superlogarithmically growing $\ell$ and $s$ make the displayed bound negligible. The same statement gives KEM IND-CPA when decapsulation queries are set to zero. A concrete native security rating requires bounds on the underlying assumptions at the simulator's resources. Correct decoding, the nonce, the known transform and byte counts alone supply no such bound.
