# Classic McEliece decoding as a fixed-challenge cubic collision

Let a Classic McEliece public key encode the binary matrix $T$ with $r=mt$ rows and $k=n-r$ columns. Here $m$ is the Goppa field degree and $t$ is the prescribed error weight. The Niederreiter encoding forms $H=[I_r\mid T]$ and returns the binary syndrome $C=He$ of the sender's weight-$t$ error vector. We describe an exact public representation of that search problem in SG-DIFRA. The security foundation remains binary Goppa-code decoding. [Classic McEliece specification, sections 4.3, 5.5 and 6.2](https://classic.mceliece.org/mceliece-spec-20221023.pdf)

## Equivalence theorem

For an input $(T,C,t)$, we can produce in polynomial time a ternary potential $P$ of degree at most three and a specified direction $h_c=(1,c,0)$. Its zero-difference starting points are in one-to-one correspondence with the binary vectors $e$ of **integer** weight $t$ and syndrome $C$. Both directions preserve a given witness in polynomial time. A public encoding inverse recovers the binary instance from the generated potential and direction. This holds for any binary systematic matrix of the stated dimensions, including honest Goppa keys.

**Circuit.** Use ternary wires $x_0,\ldots,x_{n-1}$. First output $x_i^2-x_i$ for each coordinate and require these outputs to be zero. In the ternary field this holds exactly for $x_i\in\{0,1\}$. To compute binary exclusive-or on the remaining bit wires, use $u+v+uv$ in the ternary field. The cases $00,01,10,11$ give $0,1,1,0$. Compute each row of the syndrome by starting with $x_i$ from the identity block and folding this exclusive-or into the selected bits from the $T$ block. Ternary row addition would be incorrect.

Use a binary counter of $\lfloor\log_2 n\rfloor+1$ bits to count the ones. For an old bit and carry $u,v$, update that bit to $u+v+uv$ and send $uv$ as the new carry. Add each input bit in order. This counts up to $n$ without overflow. Let the full ordered output be $B_T(x)=(\text{bit checks},\text{binary syndrome},\text{weight bits})$ and choose $c=(0^n,C,\mathrm{bin}(t))$, writing the weight bits low-order first.

**Cubic lifting.** Compile the circuit using the [Round 12 potential compiler](../round12/differential_bridge.py) and include the serialized $T$ and dimensions as an inert public tag. The pinning equations force the initial clock and challenge coordinates to zero. Each gate then forces its output from its inputs, and the final outputs must equal $c$. Every binary error vector with the required syndrome and weight therefore lifts to exactly one full collision witness $z=(0,0^{|c|},e,\mathrm{gates}(e))$. Conversely any valid collision basepoint yields such a binary error vector in its $n$ input-wire coordinates. Decoding the public tag and the challenge recovers the input instance on the image of the construction. The counter and row calculations take $O(n\log(n+1)+r+\mathrm{wt}(T))$ arithmetic gates. The public tag has $O(r\lceil k/8\rceil + \log(n+1))$ bytes. The compiler emits a sparse degree-at-most-three vector potential with polynomial total size.

On honestly generated Classic McEliece challenges, private decoding guarantees a unique error of the specified weight. The same is then true of the compiled basepoint. Feeding the actual key and challenge distribution through the compiler thus gives a generated SG-DIFRA fixed-challenge search distribution with equivalent witness-recovery success, up to conversion cost. This is a representation result for binary syndrome decoding. The established QROM proof for the model Classic McEliece transform relates its chosen-ciphertext security to one-way decoding and the implicit-rejection terms. The designers separately analyze concrete key generation and hash instantiation. This bridge identifies the underlying search predicate and preserves the distribution; it gives no independent numerical lower bound or worst-case universal-decision theorem. The theory and deployment costs of the separately designed ternary KEM remain distinct. [Classic McEliece security guide, sections 2, 5.3–5.5](https://classic.mceliece.org/mceliece-security-20221023.pdf)

**Composed model-game implication.** In the advantage conventions and reduction resources of the security guide, section 5.3.2, the bound for the correct deterministic model PKE has the form $a\le 2\sqrt p+2b$. Here $a$ is the QROM IND-CCA2 advantage, $p$ the constructed solver's probability of recovering the honest binary error, and $b$ the implicit-rejection PRF distinguishing advantage. The failure and injectivity terms vanish. For a uniform independent $n$-bit rejection string and the guide's ideal hash, it bounds $b$ by $2q_H/2^{n/2}$ at the PRF tester's hash-query budget $q_H$. The binary-to-ternary lifting above converts the solver's output to a valid full SG-DIFRA witness on the same generated instance with the same success. Consequently the model reduction yields witness success at least $(\max(0,a-2b)/2)^2$. This composition uses the guard conditions of the published conversion. The guide's section 5.5 addresses the separate transition to the specified seeded algorithms. Section 5.3.3 explains the ideal-hash boundary.

## Public wire verification

The [byte checker](binary_bridge.py) reads $T$ row by row. Every row takes $\lceil k/8\rceil$ bytes; its first bit is the low bit of its first byte. The vector $e$ and syndrome $C$ use the same bit order and respectively occupy $\lceil n/8\rceil$ and $\lceil r/8\rceil$ bytes. The checker accepts canonical encodings, including zero unused high bits. The specification distinguishes simply decoded and narrowly decoded conventions for nonzero padding. The three selected real profiles have aligned rows, ciphertexts and vectors, so no padding distinction occurs on those wires.

The [tests](test_binary_bridge.py) enumerate all trit assignments to a four-coordinate instance. They check actual finite differences, bit constraints, binary parity and integer weight. For each of three full native key pairs, a further test constructs a ciphertext from a deliberately supplied error pattern, computes the specified 32-byte key as SHAKE256 over the domain byte 1 followed by $e$ and $C$, and compares with the native receiver's decapsulation output. Fixed errors serve only as reproducible test fixtures. The actual KEM samples fresh errors with its native fixed-weight sampler. The tests expand cubic potentials only for the toy calculations; the public binary evaluator executes directly on full-size wire keys.
